## Формат записи

64 байта, little-endian, раскладка — побайтно, а не через `struct`
(упаковка `struct` у gcc для ARM и у хостового компилятора могла бы разойтись).
64 делит страницу 256 Б нацело: запись никогда не пересекает страницу и пишется одним Page Program.

| Байты | Поле |
|---|---|
| 0 | тип: `'M'` замер, `'T'` текст старого архива, `'F'` начало файла импорта, `'E'` конец импорта; 0xFF — стёрто |
| 1 | версия формата (1) |
| 2..5 | `seq`. Привязан к слоту: каждый занятый слот тратит один номер, даже испорченный |
| 6..59 | нагрузка, 54 байта |
| 60..63 | CRC32 (IEEE, как в zip) по байтам 0..59 |

Нагрузка замера: метка (год−2000, месяц, день, час, минута, секунда — 6 байт), шесть `float`
(air_temp, air_hum, soil_temp, soil_hum, vbat, vdd), bat_pct, `soil_raw`/`bat_raw` в `uint16`
(0xFFFF = nan), 16 бит флагов и кодов (bat_valid, bat_low, lse_ok, time_ok, aht_init/read 2+2,
ds_err 4, air_xchk 2, i2c_rec 2), sens_off и reset_cause по `uint16`, write_fails,
lowpower_skips и boot_count по `uint32`; 1 байт резерва.

Хранятся входы прежнего `snprintf`, а не готовая строка. `LogRecord_FormatCsv` вычисляет
из них ровно то же, что раньше: `nan` в bat_pct/vbat при `!bat_valid`,
`soil_valid = valid && !low`. Упаковка насыщает значения, которые шире своего поля, но прошивка
таких не порождает: коды HAL 0..3, ds_err ≤ 8, sens_off ≤ 360, отсчёты 12-битные.
Метка всегда фиксированной ширины: BCD-поля RTC дают не больше двух цифр.
Если метку разобрать не удалось, пишется `xxxx-xx-xx xx:xx:xx` — заметная дыра вместо
правдоподобной даты.

Строка заканчивается одним `"\n"`, как и раньше: на диск старый код писал `"\r\n"`,
потому что перевод разворачивал `f_puts`. **Для П5б:** при сборке `data.txt` ставить `\r\n`,
чтобы файл совпадал со старыми. Заголовок — `LOG_CSV_HEADER` (без перевода строки).
`CSV_HEADER` в `main.c` оставлен как синоним, его знают инструменты.

Текст импорта: `'T'` — номер файла, длина 1..52, байты как есть. `'F'` — номер, размер,
имя 8.3 и сколько байт начала файла срезано (байты 18..21 нагрузки). `'E'` — число файлов,
всего байт и сколько файлов не поместилось или не прочлось (байт 5).

## Журнал: устройство

- 512 секторов × 64 слота. Пишется только по стёртому. Как только запись перешла в новый
  сектор, следующий за ним («запасной») стирается сразу. После любой записи впереди
  остаётся стёртый сектор (тест проверяет это после каждой записи). Стирание уносит старейшие
  64 записи (G1).
- Восстановление (`LogRing_Mount`) ничего не пишет:
  1. Читается слот 0 каждого сектора. Если он испорчен, но похож на недописанную нашу
     запись (байт типа — надмножество одного из типов по единицам), смотрятся следующие слоты.
  2. Голова — сектор с наибольшим `seq`; позиция записи — за последним нестёртым слотом.
  3. Хвост ищется назад от головы, пока номера соседних секторов отличаются ровно на 64.
     Запасной сектор и пустой сектор записи в журнал не входят.
  4. Запасной сектор (и сектор записи, если запись начнётся с его слота 0) первая дозапись
     после старта стирает безусловно, а первый стёртый слот головы пропускает (T4, см. ниже).
- Если сбой не записал ни бита, слот не тратится: за стёртым слотом не должно быть записанных.
  Если записалось частично, слот тратит номер, и делается одна повторная попытка в следующий.
  Каждая запись сверяется чтением.

## API чтения для П5б

```c
uint8_t  LogArchive_Open(LogRing *r, const LogFlashOps *ops, uint32_t nsect,
                         uint8_t may_write, LogOldVolume *scratch);   // при старте, вызывает main
uint32_t LogRing_Count(const LogRing *r);      // слотов в журнале, O(1)
uint32_t LogRing_FirstSeq(const LogRing *r);   // seq старейшей, O(1)
uint8_t  LogRing_Read(const LogRing *r, uint32_t i, LogRecord *out);  // i-я от старейшей
uint8_t  LogRing_Newest(const LogRing *r, LogRecord *out, uint32_t *idx);
int      LogRecord_FormatCsv(const LogRecord *r, char *out, size_t size); // строка замера, -1 — не замер
uint32_t LogRecord_Text(const LogRecord *r, const uint8_t **text, uint8_t *file); // текст импорта
uint8_t  LogRecord_Type(const LogRecord *r);
```

- `LogRing_Newest` возвращает `LOG_READ_OK`, `LOG_READ_NONE` или `LOG_READ_EIO`.
  «Нет записей» и сбой чтения различаются.
- `LogRing_Read`: O(1) — одно чтение 64 Б. Возвращает `LOG_READ_OK`, `LOG_READ_BAD`
  (слот испорчен обрывом: записи нет, номер занят — строку пропустить), `LOG_READ_EIO` или
  `LOG_READ_NONE`.
- Кроме номера, проверяется и `seq` в самой записи: годная CRC при чужом номере не выдаётся.
- RAM: `LogRing` ~40 Б, буфер 64 Б на вызов. Копии журнала в RAM нет.
- Порядок в журнале: сначала записи импорта (`F`, `T`…, `E`), затем замеры `M`. Для
  `data_old.txt` П5б склеивает `T` по порядку. Номер файла в `T` позволяет разделить файлы,
  если понадобится.
- Ограничения:
  - Индексы сдвигаются на 64 при каждом стирании запасного сектора. Пока идёт USB-сессия,
    запись запрещена (A3), так что в сессии журнал неподвижен.
  - Чтение из прерывания OTG — только при `Storage_MscMayAccess` (флаг занятости).
  - Размер CSV заранее неизвестен: длина строки зависит от значений, так что П5б придётся один
    раз пройти журнал при монтировании (~32 тыс. чтений по 64 Б) или выбрать свою схему.
- Таблица `LogFlashOps` — `{read, program, erase, kick}`, сигнатуры как у
  `SPI_Flash_Read/Write/EraseSector`. Пункт брифа «busy» не заведён отдельно: ожидание BUSY уже
  внутри `SPI_Flash_*`, а флаг занятости для MSC ставит `main.c` на всю серию операций. Вместо
  него — `kick` для сторожа.

## Ёмкость (G6)

- 2 МБ / 64 Б = 32 768 слотов. Один сектор всегда запасной, ещё один в худший момент только
  начат. В журнале всегда не меньше **(512 − 2) × 64 = 32 640 записей**, не больше 32 703
  (тест G1 проверяет обе границы на малом кольце).
- При записи раз в час 32 640 ч = 1 360 сут = **3.72 года ≥ 3**.
- Запас — 24 %. Внеочередные замеры (KEY, VBUS) съедают его: даже 5 лишних в сутки дают 3.1 года.
- Импорт старого архива ёмкость замеров не уменьшает: тексты импорта старше всех замеров и при
  кольце уходят первыми.
- 128-байтная запись дала бы 1.86 года, поэтому 64.

## Импорт старого архива

Выбран способ «журнал в свободной области». `LogImport_Probe` находит том по MBR, по LBA 63
(стёртый MBR, R3) или с нуля. Разбирается FAT12 и FAT16; берутся `data.csv`, `data_N.txt` и
`data.txt`; граница — байт за служебной областью и за последним кластером переносимых файлов.

- Журнал импорта начинается с первого сектора выше границы. До `IMPORT_END` он вниз не
  заворачивает — это проверяется до начала, — так что старый том цел.
- При обрыве журнал при следующем старте кончается на `F`/`T`. Тогда журнальная область выше
  границы стирается, и импорт идёт заново. Граница выводится из нетронутого тома, поэтому
  совпадает при каждом повторе.
- Порядок переноса: `data.csv` → `data_N.txt` по N → `data.txt`.
- Если места не хватает (архив больше ~0.9 МБ):
  1. Сначала выпадают самые старые файлы.
  2. Если не влезает и один файл, переносятся его первая строка (заголовок) и самый новый хвост,
     начиная с границы строки. Срез отмечается в `IMPORT_FILE`.
  3. Если не влезло ничего, журнал начинается с нуля, но первой записью идёт `IMPORT_END` с
     числом выпавших файлов — потеря видна.

  **Решение владельца:** допустима ли такая частичная потеря. Иначе — снимать архив по USB до
  прошивки (шаг 1 ниже).
- Импорт не может заехать на старый том даже при повторах испорченных слотов: перед каждой
  записью проверяется, что ни она, ни стирание запасного не зайдут ниже границы. В расчёт места
  входят сектор перехода и запасной.

Тесты (`test_log_import`):
- FAT12 (кластер 1 КБ) и FAT16 с загрузочными секторами настоящего `f_mkfs`; файлы подряд и
  вперемешку. Тексты в журнале совпадают байт в байт, том ниже границы не тронут, повторного
  импорта нет.
- Обрыв на каждой операции записи импорта (каждая пятая точка — с вторым обрывом во время
  повтора): архив цел, импорт доведён.
- Сбой чтения при проверке незаконченного импорта: открытие возвращает `EIO`, следующее
  доводит импорт.
- Большой `data.txt`: перенесены заголовок и хвост байт в байт. «Не влезло ничего»: в журнале
  есть `IMPORT_END` с выпавшим файлом.
- Три круга после импорта, «не помещается», мусор вместо тома, пустой том.

Независимая сверка (вне репозитория, однократно):
- Образы тестового тома (`LOG_DUMP_DIR=<папка> build/tests/t`) прочитал `pyfatfs`: файлы
  совпали с ожидаемыми.
- Обратная сверка: том `mkfs.fat` + `mcopy` (без MBR, LBA 63). Импорт перенёс
  `data_1`, `data_3`, `data.txt` байт в байт, а чужой `notes.txt` пропустил.

## Мутации

Скрипт меняет одну строку, собирает и прогоняет тесты, затем возвращает файл. Все мутации,
кроме двух недиагностических, убиты.

| № | Мутация | Что упало |
|---|---|---|
| M1 | нет ленивого стирания запасного (после старта) | G2: «обрыв вида 0..3» (после восстановления впереди нет стёртого) |
| M19 | нет стирания заранее при переходе в сектор | G1: «после каждой записи сектор впереди стёрт», границы (N−2)/(N−1) |
| M2 | голова — наименьший seq | G1 перемонтирование, G2 все виды, G4 |
| M3 | позиция записи — на последнем нестёртом | G1, G2 все виды |
| M4 | запасной входит в хвост | G2 «обрыв вида 3» (часть записей стирания уцелела) |
| M5 | хвост без проверки смежности номеров | «сектор с несмежным номером к хвосту не пристёгнут» |
| M6 | чтение без сверки seq | «годная запись не на своём месте — не своя» |
| M7 | без CRC | «любая одиночная ошибка бита ловится» |
| M8 | стирать запасной на каждой записи | G4 «сектор стирается один раз за круг» |
| M9 | незаконченный импорт не замечается | «обрыв посреди импорта… импорт доведён» |
| M10 | журнал импорта с сектора 0 | «старый том не тронут», совпадение текстов |
| M11 | `data.txt` не последним | порядок файлов, совпадение текстов |
| M12 | сектор за полной головой не проверяется на чистоту | «двойной обрыв: сектор стёрт заново» |
| M13 | недописанный слот 0 считается чужим | «сбой в слоте 0 (частично): все 84 записи на месте» |
| M14 | без повторной попытки записи | «сбой программирования — повтор удался» |
| M15 | форматтер: soil_valid без `!low` | «строка 2 совпала с эталоном» |
| M16 | упаковка теряет aht_read_st | строки 1–3 эталона |
| M17 | сектор записи на чужой флеш не стирается | «мусор: журнал пишется поверх и читается» |
| M18 | граница тома без кластеров файлов | граница и совпадение текстов |
| M20 | пустой после сбоя слот тратится | «сбой в слоте 0 (пусто): все 84 записи на месте» |
| M21 | сбой чтения сверки — слот тратится, повтор | «сбой записи и чтения сверки — отказ без повтора» |
| M22 | EIO при проверке импорта = «импорта нет» | «сбой чтения при проверке импорта — EIO» |
| M23 | без среза начала файла | «большой data.txt: срез отмечен / заголовок / хвост / объём» |
| M24 | без `IMPORT_END`, когда не влезло ничего | «не влезло ничего: … IMPORT_END с одним выпавшим файлом» |
| M25 | срез без заголовка | «большой data.txt: заголовок сохранён», «хвост байт в байт» |

Инспектор независимо перепроверил на копии репозитория ещё пять мутаций, и каждая уронила свой
тест:
- смежность номеров в хвосте;
- сверка `seq` при чтении;
- стирание заранее;
- перестановка полубайтов FAT12;
- `LogImport_Pending` всегда 0.

Первый прогон мутаций нашёл настоящую ошибку (M13/M20). Если сбой шины в слоте 0 сектора не
записывал ни бита, следующая запись уходила в слот 1. При перезапуске сектор со стёртым слотом 0
считался пустым и стирался вместе с записями за ним. Исправлено: такой слот не тратится. M1, M4,
M5, M6 и M12 сначала выжили; под них добавлены тесты (вид обрыва 3, несмежный сектор, запись не
на месте, двойной обрыв).

## Остаточные риски

- **Очередь USB-сессии живёт в RAM.** Если между отключением кабеля и следующим циклом (до часа)
  случится сброс, эти замеры пропадут. Сливать очередь сразу при выходе из сессии значило бы
  править `SleepUntilNextSample` (сон, вне узкой сессии).
- **Чужое содержимое без узнаваемого тома** журнал перезаписывает по мере хода кольца. Решение
  в пользу G1: прибор пишет всегда. Старая прошивка такую флеш не форматировала.
- **После импорта старый том остаётся на флеш, пока кольцо его не сотрёт.** Каждый старт
  дочитывает его сектора, похожие на наши (обычно не все). Худший случай — до ~0.9 МБ чтения
  на старт; обычно десятки КБ.
- **Сессия USB дольше 48 ч:** очередь (48 записей) переполняется, лишние замеры теряются, это
  видно только по `write_fails`. Во время сессии питание не проверяется — запись идёт позже,
  уже по правилу питания.
- **Хостовые тесты идут ~50 с без `-O2`** — перебор обрывов G2, вида 4 и отказов чтения
  при импорте. Полный перебор отказов чтения при незаконченном импорте — `LOG_FULL=1` (~75 с с `-O2`).

### T1 — три исхода разбора

- `LogImport_Probe` возвращает `LOG_PROBE_VOL` / `LOG_PROBE_NONE` / `LOG_PROBE_EIO`. Любой отказ
  чтения (MBR, загрузочный, корень, FAT в `CheckChain`) — сразу `EIO`, без перехода к следующему
  кандидату (раньше отказ LBA 63 случайно переживался повтором кандидата из MBR).
- `LogImport_NextClust` отличает сбой чтения (`LOG_CLUST_EIO`) от битой цепочки. Это проверяется
  во всех местах: `CheckChain` (→ `EIO`), `Seek` и `Get` при самом переносе (→ отказ импорта,
  `LOG_OPEN_FAIL`, повтор со стиранием журнальной области). Перебор нашёл здесь дыру первой
  версии правки: `Seek`/`Get` принимали `LOG_CLUST_EIO` за номер кластера и переносили мусор.
- `LogImport_AfterNl` (заголовок и хвост обрезанного файла) отличает «перевода строки нет» от
  сбоя (`LOG_NL_EIO`). Раньше сбой давал пустой файл и закрытый «удачный» импорт.
- `LogArchive_Open`: при `EIO` разбора ничего не пишет и отвечает `LOG_OPEN_EIO`. Перед любой
  записью (первый старт и незаконченный импорт) разбор делается дважды и должен совпасть (`vol`,
  `end`, `nfiles`, `total`). Только тогда журнал начинается, стирается область выше границы или
  закрывается импорт при уверенном «тома нет». Так ловится и искажённое, а не отказавшее чтение.
- У битой (прочитанной) цепочки пройденные кластеры всё равно входят в границу.
- `main.c` уже повторяет `EIO` трижды с `SPI_Flash_Init` и затем в каждом цикле.

Тесты (`test_log_import`):
- сценарии стенда: отказ LBA 63, корня LBA 96, записи FAT первого кластера `data.txt` на первом
  старте — `EIO`, `fm_ops` не изменился, том цел; повтор переносит все три файла;
- незаконченный импорт + отказ корня — `EIO`, ничего не стёрто; следующий старт доводит импорт;
- искажённое чтение корня (первый байт обнулён — «каталог пуст») на первом старте и при
  незаконченном импорте — разборы не совпали, `EIO`, записей нет; следующее открытие переносит всё;
- перебор «отказывает k-е чтение» для каждого k: первый старт (1228 точек), незаконченный импорт
  (подряд первые 1200 — монтирование, проверка импорта, оба разбора, около 650 чтений; дальше
  каждое 499-е; `LOG_FULL=1` — все ~35 тыс., проходит), обрезанный большой `data.txt` (1475
  точек, итог совпадает с импортом без сбоя). Критерии: при `EIO` записей нет, том ниже границы
  не тронут, после повторов все файлы перенесены байт в байт.

### T2 — снятие защиты

- `LogFlashOps.unlock` (новое поле, может быть `NULL`): журнал снимает защиту перед каждой
  записью (`LogRing_Append`) и ещё раз перед повтором, а импорт — перед стиранием журнальной
  области. Не снялась — отказ, `fs_ok = 0`, следующий `Archive_Open` переинициализирует флеш.
- Стирание проверяется чтением сектора (`LogRing_EraseSect`): запертый чип отвечает на стирание
  «успехом». Без этой проверки запасной считался бы стёртым со старыми данными внутри.
- `SPI_Flash_Unlock` (spiflash.c): `WaitBusy` + `WREN` + `0x98` + `WaitBusy` с проверкой каждого
  шага; у SST26 (JEDEC 0xBF) — ещё чтение BPR (`0x72`, 6 байт, все нули). У совместимых чипов без
  BPR проверки регистром нет, остаётся сверка каждой записи чтением.
- `Archive_Open` вызывает `SPI_Flash_Init` перед каждой попыткой, включая первую.
- Модель: `fm_locked` (program/erase «успешны», ничего не делают), `fm_lock_at` (запереть перед
  операцией с номером), `fm_unlock_fail`.
- Тесты (`test_log_ring_accept2`): запирание каждые 7 записей — все 500 прошли; запирание перед
  каждой из 190 операций серии на кольце, прошедшем круг, — ни одного отказа и ни одной
  испорченной записи, запись возобновляется в том же вызове; защита не снялась дважды — отказ без
  порчи, после переоткрытия запись идёт.

### T3 — классификация сектора

- Слот 0 не похож на наш (байт типа не надмножество типа) — чтение идёт дальше: стёртые слоты
  (в том числе пропуск после старта, T4) и похожие на наши недописанные пропускаются, годная CRC с
  номером — сектор наш. Первый «чужой» слот — сектор чужой, напоследок смотрится ещё слот 63. На
  чужом томе это два-три лишних чтения на сектор. (Первая версия смотрела только слоты 1 и 63, и
  инспектор показал дыру: см. ниже.)
- В обходе хвоста сектор без годного номера (испорчен целиком, но не стёрт) не рвёт журнал, если
  предыдущий за ним продолжает нумерацию ровно через сектор (−128). Он остаётся внутри и читается
  испорченными слотами. Запасной и сектор записи мостом не перешагиваются.
- Голова со сброшенным битом теперь узнаётся как голова, поэтому не стирается.
- Тесты:
  - все сбросы 1→0 в байтах 0..5 слота 0 (21 случай с единичными битами): в середине кольца, в
    голове и в голове, где после записи слота 0 был перезапуск (слот 1 стёрт пропуском). `Count`
    не меняется, теряется только этот слот, дозапись не стирает голову;
  - сектор нулей посреди журнала — выпадают только его 64 записи;
  - испорчен старейший сектор, а за ним запасной с уцелевшими после оборванного стирания записями
    (номер ровно на сектор меньше) — мост его не пристёгивает.

### T4 — слабые ячейки: обоснование

Оборванное стирание NOR может остановиться, когда ячейки уже читаются как 1, но с малым запасом
заряда; оборванное программирование — когда ячейки сдвинуты, но ещё читаются как 1. Чтение
этого не видит, а сверка после записи проходит, и биты уплывают позже (время, температура). Самое
вероятное место обрыва на садящейся банке — как раз стирание (пик тока). Поэтому решение не
опирается на чтение:
- после монтирования запасной сектор и сектор записи, если запись начнётся с его слота 0,
  стираются первой же дозаписью безусловно. Оба вне журнала, потерь нет. Цена — одно-два
  стирания по 25 мс на старт; старты редки (замена банки, сторож, прошивка). Тест G4 с
  перезапуском каждые 37 записей: износ остаётся ровным (разброс ≤ 4 при 20 кругах), лишних
  стираний не больше двух на старт;
- первый стёртый слот головы пропускается (тратит номер) при первой дозаписи. Если обрыв пришёлся
  на программирование этого слота без единого сброшенного бита, поверх слабых ячеек ничего не
  пишется. Цена — один слот (запись читается как `LOG_READ_BAD`) на старт. Пропуск делается в
  RAM при первой записи, так что старт без записи не тратит ничего. Для `Mount` и `Read` это
  обычный испорченный слот; стёртый слот после слота 0 восстановлению не мешает.
- Модель: вид обрыва 4 — сектор/слот читается 0xFF, но помечен слабым; `fm_age()` сбрасывает
  случайные единицы в слабых местах (в том числе у записанного поверх); полное стирание лечит.
- Тест: обрыв вида 4 на каждой из 717 операций, затем два сектора дозаписи, «старение» и
  перезапуск — все подтверждённые моложе хвоста на месте, испорченных не больше одного, кроме
  стёртых пропусков.

### T5, T6, T7

- T5: `LogImport_Room` — одна проверка перед каждой записью импорта: FILE, TEXT и END. Тест:
