# П5а — кольцевой журнал (волна 3, сессия 1 из 3)

Ветка: `fix/p5a-log-ring`. Сначала: `audit/briefs/_common.md` (включая инспектора),
`audit/briefs/P5_overview.md` (архитектура и гарантии G1–G6), затем этот бриф.

## Владение
Новые `Core/Inc/log_record.h`, `Core/Inc/log_ring.h` (single-header, см. обзор);
`Core/Src/spiflash.c`/`.h` (включает реализацию журнала, добавляет нужные операции флеш);
`Core/Src/main.c` — блоки монтирования/форматирования/сверки заголовка/дозаписи строки
(они заменяются журналом) и формирование строки CSV (переезжает в форматтер);
`Core/Inc/storage_policy.h` (правила, которые больше не нужны, — удалить вместе с тестами;
`Storage_MayWrite` и порог батареи сохраняются); `tests/test_main.c` (новые разделы).
**Не трогать:** `usbd_storage_if.c` и всё про USB-том (это П5б), `tools/` (П5в).
USB в этой сессии временно остаётся как есть: отдаёт сырые сектора флеш, том хост не
распознает — это ожидаемо до П5б, запиши в отчёт.

## Что сделать

1. **`log_record.h`** — двоичная запись замера фиксированного размера (выбери и обоснуй:
   кратно странице 256 Б, все 23 поля текущей строки CSV, версия формата, номер записи
   `seq`, CRC32). Плюс **форматтер** `LogRecord_FormatCsv(const LogRecord*, char*, size_t)`
   и строка заголовка — перенос текущего `snprintf` из `main.c` **без изменения формата
   вывода**: тест сравнивает вывод форматтера с эталонными строками, снятыми с текущего
   кода до правки. Плюс тип записи «текст старого архива» для импорта (п. 4).
2. **`log_ring.h`** — журнал на всей физической флеш:
   - запись только программированием по чистой памяти; стирание следующего сектора
     **заранее** (всегда держать минимум один стёртый сектор впереди головы);
   - при нехватке места стирается сектор со старейшими записями (G1);
   - восстановление головы и хвоста при старте сканированием (по первому `seq` каждого
     сектора — без чтения всего чипа), запись с битым CRC или недописанная пропускается (G2);
   - чтение для П5б: `LogRing_Count()`, чтение i-й записи от старейшей (за O(1) или
     O(число секторов)), без копии журнала в RAM;
   - доступ к флеш — через таблицу функций (read / program / erase / busy) — на хосте модель.
3. **`main.c`** — путь записи: замер → `LogRecord` → журнал. Сохранить: `Storage_MayWrite`
   (порог батареи), флаг занятости флеш, «во время USB-сессии не писать, держать в RAM и
   записать после» (A3), счётчики `write_fails`/`lowpower_skips`, сторожевой таймер (пинки
   в долгих операциях: стирание сектора до ~400 мс, сканирование при старте).
   FatFS из пути записи убрать; middleware оставить в сборке.
4. **Импорт старого архива (одноразово).** Если при первом старте на флеше обнаружен старый
   FAT-том с `data.txt`/`data_N.txt` — до того как журнал займёт флеш, скопировать их
   **текст как есть** в RAM-буфер порциями и записать в журнал записями типа «текст
   старого архива» (порядок: старейший `data_N` → `data.txt`), затем инициализировать
   журнал поверх. Обрыв питания посреди импорта не должен терять старый архив: журнал
   начинать с области, где нет данных старого тома, или импортировать в два прохода —
   обоснуй выбранный способ и покрой тестом на модели флеш с обрывом.
5. **Тесты (обязательно, это и есть гарантии):** модель флеш на хосте (NOR: программирование
   только 1→0, стирание сектора в 0xFF, счётчик стираний, обрыв после произвольной операции).
   - G1: 10+ полных кругов кольца, порядок и непрерывность `seq`, старейшие уходят посекторно.
   - G2: обрыв после каждой операции программирования и стирания на нескольких кругах →
     после восстановления потеряно не больше одной записи (плюс старейший сектор при обрыве
     его стирания), ни одной записи с чужими данными.
   - G4: разброс счётчиков стираний по секторам после N кругов.
   - G6: в отчёте — расчёт ёмкости при выбранном размере записи (лет при записи раз в час).
   - Импорт: старый том на модели → тексты в журнале совпадают байт-в-байт; обрыв посреди.
   Мутации — как в `_common.md`, по каждому правилу.

## Готово, когда
Общий критерий `_common.md` + G1, G2, G4, G6 и импорт закрыты тестами; инспектор без открытых
БЛОК/ВАЖНО; отчёт `audit/reports/p5a-log-ring.md` описывает API чтения для П5б (сигнатуры,
сложность, ограничения) и формат записи. Держи сессию узкой: не трогай сон, датчики, USB.
