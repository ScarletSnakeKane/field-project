# П5б — виртуальный том для USB (волна 3, сессия 2 из 3)

Ветка: `fix/p5b-virtual-fat`, от ветки-основы **после слияния П5а**. Сначала:
`audit/briefs/_common.md`, `audit/briefs/P5_overview.md`, отчёт `audit/reports/p5a-log-ring.md`
(API журнала и формат записи), затем этот бриф.

## Владение
Новый `Core/Inc/vfat.h` (single-header); `USB_DEVICE/App/usbd_storage_if.c` (USER CODE);
в `main.c` — только начало и конец USB-сессии (подготовка тома при подключении);
`tests/test_main.c` (новый раздел) и при необходимости хостовый тест на Python
`tests/test_vfat_image.py`. Журнал (`log_ring.h`, `log_record.h`) — только вызывать,
не менять; если без правки не обойтись — в отчёт «вне владения».

## Что сделать

1. **`vfat.h`** — генератор секторов FAT-тома только для чтения:
   - FAT16 (Android не монтирует FAT12 — история проекта), размер тома и кластера —
     обоснуй так, чтобы влез `data.txt` максимального размера (весь журнал в CSV) с запасом,
     и число кластеров было в диапазоне FAT16;
   - MBR + загрузочный сектор + две FAT + корневой каталог + данные; цепочки FAT —
     арифметически (файлы непрерывны); метка тома `FIELDSENSOR`;
   - файлы: `data.txt` (заголовок + строки от старой к новой), `data_old.txt` (только пока
     в журнале есть записи импорта), по желанию `info.txt` (версия прошивки, число записей,
     диапазон времени, счётчики отказов) — коротко;
   - дата и время файла в каталоге — по последней записи (если `time_ok`), иначе фиксированная;
   - смещение в файле → запись: разреженный индекс (например, каждая 64-я запись), строится
     при подключении USB; RAM — обоснуй (у F401 96 КБ, у U073 v2 — 40 КБ, держи в пределах
     нескольких КБ); далее форматирование вперёд от ближайшей точки индекса;
   - размер файла фиксируется при подключении: журнал во время сессии не меняется (A3).
2. **`usbd_storage_if.c`** — `GetCapacity` по виртуальному тому, `IsWriteProtected` = защищён,
   `Write` — отказ, `Read` — из `vfat.h`. Длинные чтения не должны держать USB-прерывание
   дольше разумного: оцени время форматирования одного сектора 512 Б в худшем случае.
3. **Тесты (это гарантия G5):**
   - C-тест: собрать образ тома в файл для журнала на модели (пустой, 1 запись, частично
     заполненный, после нескольких кругов кольца, с импортом и без);
   - независимая проверка образа: `fsck.vfat -n` и `mtools` (`apt-get install -y dosfstools mtools`),
     если недоступны — `pip install pyfatfs`; на Windows у владельца тест пропускается с
     сообщением, а не падает;
   - извлечённый `data.txt` совпадает байт-в-байт с CSV, собранным форматтером напрямую
     из записей; чтение секторов в случайном порядке даёт тот же образ, что и по порядку.
   Мутации — как в `_common.md`.

## Готово, когда
Общий критерий + G3 и G5 закрыты; инспектор без открытых БЛОК/ВАЖНО; в отчёте
`audit/reports/p5b-virtual-fat.md` — шаги проверки на плате: Windows, Android-телефон
заказчика, копирование во время ежечасного пробуждения.
