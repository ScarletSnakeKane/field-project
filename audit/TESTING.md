## Плата
STM32F401 (проект собран под F401RET6; BlackPill F401CEU6 совместим, CCU6 — нет).
Пины: PB0 ключ датчиков (HIGH = выкл), PB8/PB9 I2C (AHT20 0x38 + BMP280 0x76/0x77),
PA8 1-Wire DS18B20, PA1 почва (ADC1_IN1), PA2 делитель батареи (ADC1_IN2, ×2),
PA4–PA7 SPI-флеш SST26VF016B (CS, SCK, MISO, MOSI), PA9 VBUS-детект, PA11/PA12 USB,
PA0 кнопка KEY, PC14/PC15 LSE, PA13/PA14 SWD.

## Как работает прошивка (кратко)
- Раз в час: питание датчиков → замер → одна двоичная запись в кольцевой журнал на флеш → сон.
  Каждые ~15 с короткое пробуждение только для сторожа IWDG (без замера).
- Кнопка — внеочередной замер. **Вокруг USB-сессии не меряем** (прибор вынут из земли):
  вставка кабеля будит без замера, часовые замеры при открытой сессии пропускаются;
  зарядка без хоста через 10 с отпускает плату, расписание идёт обычно.
- По USB — виртуальный FAT16-том `FIELDSENSOR` только для чтения: `data.txt` (CSV, 23 колонки),
  `info.txt`, пока жив импорт — `data_old.txt`. Диск появляется через ~1–13 с (растёт с архивом).
- Журнал на отдельной SPI-флеш: перепрошивка МК архив **не стирает**. Ёмкость ~3.7 года.

## Передача: правка расписания замеров (2026-10-29)

Ветка `claude/hopeful-dijkstra-dd2221`, коммит 3009f69 **поверх a4df667** (то есть поверх
ветки испытаний). Отдельного PR нет; вливать в `claude/vigilant-wright-2gtdxe` до слияния
PR #7 либо брать черри-пиком.

**Что было не так.** Остаток сна был локальной переменной: при каждом входе в сон бралось
`RTC_WAKEUP_INTERVAL_SEC` заново. Сон нарезан кусками по 15 с ради сторожа, и досрочный
выход из цикла кусков (фронт VBUS или кнопка) выбрасывал всё отспанное — следующий сон
начинался с полного часа. Каждое досрочное пробуждение молча стоило часа наблюдений;
в данных это не видно ничем, кроме редеющего архива. На модели: фронты VBUS раз в
50 минут — 29 строк за двое суток вместо 48.

**Что сделано.** Время с прошлого ЗАМЕРА копит `Policy_Schedule` (`power_policy.c`):
в него идут и отспанные куски (сразу по отработке каждого), и бодрствование в цикле
удержания. Спим остаток, а не интервал. Обнуляет отсчёт только состоявшийся замер;
пропуск вокруг USB-сессии — нет, внеочередной замер по кнопке — да. Прибавка с
насыщением (долг не копится), остаток вверх до секунды, при старте и после сброса —
полный интервал (первый проход меряет сразу). Потолки сессии USB, признак `usb_started`
и порядок `Usb_Stop()` / `SPI_Flash_DeepPowerDown()` из a4df667 не тронуты.

**Проверки без платы:** `syncheck: OK`, хостовые тесты 547/0 (было 520/0), 9 мутаций —
8 убиты, M7 (`>` вместо `>=`) эквивалентный. Модель потока теперь считает строки впритык
(интервалом реже — тест падает) и не висит, если прибор перестаёт засыпать.

**На живом железе НЕ проверено** (в облаке нет платы и ARM-тулчейна; под плату не
собиралось вовсе). Проверить на стендовом интервале (`RTC_WAKEUP_INTERVAL_SEC = 60U`
в `rtc.h`): ткнуть кабелем или нажать KEY на ~40-й секунде — шаг строк обязан остаться
~60 с, а не разъехаться на 100 с. Отдельно: после нескольких досрочных пробуждений плата
просыпается САМА (в `reset_cause` нет бита 16 — сторож), и средний ток в поле без USB
не изменился.

**Инспектору** (субагент, только чтение; `audit/briefs/_common.md`, раздел «Инспектор»):
дифф `git diff a4df667 3009f69`; владение — только `Core/Inc/power_policy.h`,
`Core/Src/power_policy.c`, `Core/Src/main.c`, `tests/test_main.c`. Смотреть: не зачитывается
ли время ДВАЖДЫ (тик в STOP стоит, куски зачитываются отдельно); остался ли `armed`
локальным (статический увёл бы плату в STOP без будильника); путь `left == 0` (сна нет);
не появилось ли пути, где прибор молчит дольше одного интервала или мерит заметно чаще
часа; нет ли в новых тестах проверок, которые не могут упасть.

## План испытаний
1. Первые строки на новой прошивке: `aht_read_st`, `air_xchk`, `ds_err` (5 = клон DS18B20 с
   иными служебными байтами), `soil_valid`/`soil_raw`, `vbat`/`vdd`, `lse_ok`, `time_ok`.
2. Сутки на столе от банки, **без USB и ST-Link**: ~24 строки, время без дыр; подключение
   телефона лишней строки не даёт; кнопка — даёт.
3. Ток сна амперметром в разрыв банки, ST-Link физически отключён.
4. Несколько выдёргиваний банки во время работы — файл читается, потеряно ≤ 1 строки.
5. Телефон заказчика: диск появляется, файл копируется.
6. Перед полем: BOR Level 3 в option bytes (STM32CubeProgrammer → OB → `BOR_LEV`).
7. Всё прошло — слить PR #7 в `main`.
